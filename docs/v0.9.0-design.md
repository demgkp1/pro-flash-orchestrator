# v0.9.0 设计方案：AGY 单平台收敛与配额分档

- 状态：已评审，待实现
- 目标版本：v0.9.0（单次发布，不分阶段版本）
- 适用仓库：demgkp1/pro-flash-orchestrator
- 基线版本：v0.8.1（commit `586c456`）

## 1. 背景与决策

Pro-Flash Orchestrator 从一开始就是为 Google Antigravity 设计的模型分流策略。其他 Agent（Codex、Claude Code）已自带成熟的流量分配机制，跨平台适配对本插件没有实际收益，只带来维护成本。据此作出以下决策：

1. **插件定位为 AGY-only**，接受与 Antigravity 宿主强耦合、必须跟紧 AGY 更新这一事实，不再为跨平台抽象付出成本。
2. **删除 Codex 与 Claude Code 的全部适配代码**，收敛为单一宿主实现。
3. **配额从固定数字改为按任务规模分档**，解决固定配额在大任务上过紧、在小任务上过松的问题。
4. 对照基准实验（开/关守门的配额与质量对比）**暂缓**，不在 v0.9.0 范围内。
5. 上述两项变更**合并为一个 v0.9.0 发布**：本地测试全部通过后统一打包，不拆分多个中间版本发布。

## 2. 目标与非目标

### 目标

- 仓库内不再存在 Codex / Claude 的运行时代码、配置模板与打包路径。
- `lib.mjs` 只处理 Antigravity 的 payload 形态，删除宿主识别与字段翻译层。
- 主控读写配额由任务规模档位（S / M / L / XL）决定，M 档与 v0.8.1 现行数字完全一致，保证默认行为不回归。
- 分档判定完全确定性、零模型调用、零额外 Token 消耗。
- 判定失误时不卡死任务：轮内自动升档一次作为兜底。

### 非目标

- 不做开/关守门的对照基准实验与收益量化（暂缓，另行立项）。
- 不拆分设置面板与 Marketplace 等外围功能（随跨平台删除自然消失的部分除外）。
- 不改变 Worker 档位路由（`inherit` / `flash` / `pro`）、双轨验收契约、同批文件互斥锁、防递归、防轮询与死循环熔断的现有规则。

## 4. 第二部分：配额分档

### 4.1 设计原则

1. **M 档即现状**：现行标准策略的数字（直读 3、直写 2）原样成为 M 档，默认路径行为不回归。
2. **确定性判定**：只用规则与计数信号判定档位，不调用模型判定规模。
3. **标杆纪律不随档位放宽**：Pro 亲自落盘的标杆文件始终 ≤2 个，这是核心纪律；放宽的是直读数量、批次数与 Audit 额度。
4. **配额按批次作用**：L / XL 档通过允许多个批次获得总量，而不是单批放水；每批次的标杆与扇出上限不变。
5. **判错不卡死**：轮内撞限自动升一档并放行，每轮最多升一次，升档全程记录。

### 4.2 档位表（Pro 主会话基准）

| 档位 | 场景 | 主控直读 | 主控直写 | 标杆文件 | 并发扇出 | 批次上限 | Audit 额度上限 |
| :--- | :--- | :---: | :---: | :---: | :---: | :---: | :---: |
| S | 单文件小改、文案、修小 bug | 2 | 1 | 1 | ≤2 | 1 | 6 |
| M | 常规功能与 bug 修复（现行） | 3 | 2 | 2 | ≤5 | 1 | 10 |
| L | 多模块功能、跨前后端 | 5 | 3 | 2 | ≤5 | 2 | 14 |
| XL | 全仓重构、迁移、批量改造 | 8 | 4 | 2 / 批次 | ≤5 | 3 | 20 |

补充规则：

- Audit 动态额度规则不变：每次放行 `self` 派单 +2，改为受当前档位上限封顶（现行上限 10 即 M 档值）。
- 切片防泄洪规则不变（未切片 300–800 行收窄、超限拦截、minified 识别），与档位无关。
- 档位以**用户轮次**为周期重判；Audit 额度仍按现行规则在新轮次清零；批次计数在轮次内累计。

### 4.3 策略倍率（与档位正交）

档位表是 Pro 主会话基准，现行两套特殊策略改为倍率 / 豁免，与档位相乘叠加：

| 主会话策略 | 处理方式 |
| :--- | :--- |
| 标准主会话（Neon / Argon / Carbon） | ×1，即档位表原值 |
| Flash 主会话（`flash-main-relaxed`） | 直读、直写 ×2（与现行 6 / 4 对 M 档的结果一致），其余项不变 |
| Hydrogen 主会话 | 沿用现行路由与计数规则，套用档位表 |
| 原生 Orchestrator（Lite Guard Mode） | 计数豁免不变，仅保留切片、防嵌套、禁轮询、契约与互斥锁 |

实现上在 `lib.mjs` 中新增 `TIER_TABLE` 与 `resolveTaskTier()`，与现有 `capabilityStrategy()` 并列：前者决定“规模档位”，后者决定“主会话策略”，守门脚本读取二者的组合结果，不再各自写死数字。

### 4.4 档位判定

判定发生在 `PreInvocation`（每轮开始）一次，结果写入 session 状态（字段：`taskTier`、`tierSource`、`tierEscalated`），SessionStart 状态卡展示当前档位。

**信号优先级（高到低）：**

1. **显式指定（explicit）**：用户在 `/flash-dev` 指令中给出规模标记（如 `[SCALE=L]`）或规模词；或面板设置 / 环境变量 `PRO_TASK_TIER` 指定。显式指定时关闭自动升档（`tierEscalated` 恒为 false），尊重用户判断。
2. **启发式判定（heuristic）**，信号包括：
   - 本轮用户输入中提到的文件路径个数；
   - `git status --porcelain` 的改动文件数；
   - 关键词：全仓 / 迁移 / 批量 / 所有模块 → XL 候选；重构 / 跨模块 / 前后端 → L 候选。
   
   判定规则：提到 ≥6 个文件或命中 XL 关键词 → XL；3–5 个文件或命中 L 关键词 → L；仅 1 个文件且无扩散关键词 → S；其余 → M。
3. **轮内升档（escalated）**：非显式档位下，主控在本轮撞到直读 / 直写上限时，自动升一档、放行本次调用、在状态卡与日志中标注。每轮最多升一次；XL 档撞限维持现行 deny 行为。

### 4.5 风险维度（与规模正交，不进档位表）

规模管配额，风险管抽检，两者不混表：

- 命中高风险路径（鉴权、支付、数据迁移、密钥与凭据、数据库 schema）的文件，不增加任何直写配额；
- 但其 Audit 规则升级：从抽检 20–60 行改为全量查看该文件的改动行。
- 高风险路径清单维护在 `lib.mjs` 的一处常量中，守门与 Audit 共用。

### 4.6 配置与面板

- 环境变量：`PRO_TASK_TIER`（`S|M|L|XL`，显式覆盖）、`PRO_TIER_AUTO=0`（关闭启发式，固定 M 档）。
- 面板：在 v0.8.0 的 Worker 档位设置旁新增“任务规模”项，选项为 自动 / S / M / L / XL，默认自动；保存位置与 Worker 设置一致（`worker-settings.json` 同级配置）。
- `.state/mode.json` 的防代理修改保护同样覆盖档位状态：代理不得自行改写 `taskTier`，升档只能由守门脚本按 4.4 的规则触发。

### 4.7 遥测

`report.mjs` 新增分档统计：

- 各档位轮次占比（判档分布）；
- 升档次数与升档前档位（调表依据）；
- 各档位下的 deny 次数（XL 档 deny 异常升高说明表仍偏紧）。

## 5. 统一发布流程（单版本 v0.9.0）

两项变更在一个开发分支内完成，按以下顺序推进，全部本地验证通过后统一打包发布：

1. **分支开发**：从 v0.8.1 拉出 `v0.9.0` 分支；先执行第 3 节删除并修绿全部测试，再在干净代码上实现第 4 节分档。顺序不可颠倒：先删后改，改动面最小。
2. **本地 shadow 验证（不发布）**：分档实现完成后，先以 shadow 模式在本机跑数日真实 AGY 会话，只记录判档与升档日志、不实际拦截，用 `report.mjs` 检查判档分布与升档频率，据此微调 4.2 的数字与 4.4 的阈值。此阶段不占版本号。
3. **发布门禁（全绿才打包）**：
   - doctor 与全部剩余测试套件通过；
   - 第 3.3 节删除验收四项全部满足；
   - 分档测试（第 6 节）全部通过；
   - shadow 验证的判档分布无明显异常（如 S / XL 占比畸高）。
4. **打包发布 v0.9.0**：仅 AGY 一个发布包；release notes 写明：
   - 破坏性变更：删除 Codex / Claude Code 支持，Codex 用户请停留在 v0.8.1（归档分支与 Release 保留）；
   - 新特性：配额按任务规模分档，默认自动判定，可显式指定与面板覆盖。
5. **回滚预案**：因两项变更合并发布，回滚即整体回退到 v0.8.1 发布包；`.state/` 配置与日志格式保持兼容，回滚不丢状态。注意：回滚成本是合并发布的已知代价，第 2 步的本地 shadow 验证是发布前唯一低成本调表窗口，不可省略。

## 6. 测试计划

在现有套件基础上新增 / 扩展：

- **判档稳定性**：同一组输入（文件数、关键词、git 状态）多次判定结果一致；显式标记恒优先于启发式。
- **升档规则**：非显式档位每轮最多升一次；显式档位不升档；新轮次升档标记清零；XL 档撞限仍 deny。
- **批次规则**：L / XL 档进入下一批次后标杆与扇出额度重置；批次超限 deny；S / M 档第二批次派单被拦截。
- **倍率组合**：Flash 主会话在各档位下直读 / 直写为基准 ×2；原生 Orchestrator 各档位下计数豁免不变。
- **高风险抽检**：高风险路径文件的 Audit 触发全量改动行查看；普通文件仍为切片抽检。
- **删除回归**：第 3.3 节四项验收固化为 doctor 检查项，防止后续版本把跨平台残留带回来。

## 7. 风险与开放问题

- **合并发布的回滚连带**：分档出问题时回滚会连带恢复已删除的跨平台代码。缓解：本地 shadow 验证 + 门禁全绿后才发布（见第 5 节）。
- **S / XL 两档数字为初值**：S 档直读 2、XL 档直读 8 / 批次 3 缺乏真实数据支撑，需以 shadow 验证的升档频率校准；若某档升档率持续偏高，应调表而非调判定。
- **启发式误判**：关键词判定对中英混排输入的覆盖需在测试中补齐用例；误判成本由轮内升档兜底，上限为多消耗少量主控配额。
- **AGY 版本漂移**：档位判定依赖的 payload 字段与工具名随 AGY 更新可能变化，沿用现行 capabilities 探测与回归测试机制跟进，这属于 AGY-only 定位的已知成本（见第 1 节决策 1）。
